What exists today

Three pieces, all live in the public repo and passing CI. The Android app has not been tested on a real phone yet.

BUILT

Android app

  • Permission gate: needs “Allow all” photos; “Select photos” is refused
  • Unlock with fingerprint, face or passcode on every launch; no screen lock, no server
  • Foreground service runs a NanoHTTPD server on port 8080 to 8090
  • Running screen: QR code, link, Copy link, Stop server
  • Follows Wi-Fi changes; stops if access is revoked
  • Trash through Android’s own confirmation dialog
BUILT

Web gallery (served by the phone)

  • Virtualized grid for 10,000+ photos, grouped by day
  • Filters: All, Screenshots, Large files over 5 MB; sort newest or oldest
  • Selection with shift-range, per-day select, select all
  • Viewer: zoom 50% to 400%, pan, pinch, swipe, keyboard
  • Download one file, or many as a streamed zip
  • Move to trash with “Confirm on your phone” waiting state
BUILT

Landing page & releases

  • GitHub Pages page with Download APK and an “Open gallery” box
  • Link check: only private IPv4 with a port
  • Signed release built by CI on every v* tag
  • Stable URL: …/releases/latest/download/gallery.apk
  • Security: random token per start, HttpOnly SameSite cookie, private-IP clients only

How it is wired

Today the browser talks straight to the phone. Anywhere access adds a small cloud service that introduces the two, and photos still never sit on a server.

Security grows with the reach

Messages and notifications are more sensitive than photos, and the internet is bigger than your Wi-Fi.

NOW

Random token per start. HttpOnly, SameSite=Strict cookie. Only private-IP clients are accepted. Unlock required to start. Traffic is plain HTTP on your LAN.

PHASE 1

App passcode with lockout after a few wrong tries, plus a switch per feature (photos, notifications, SMS, files). Sensitive tabs stay locked until the passcode is entered. The passcode still travels over plain HTTP on the LAN.

PHASE 2

Accounts and pairing. First connection from a new browser needs approval on the phone. Revoke any browser from the app. The registry never stores photos, cookies or the passcode.

PHASE 3

End-to-end encryption between phone and browser, keys set at pairing. Rate limits, an alert on every new connection, and a Wi-Fi-only option to protect mobile data.

PHASE 4

Screen control permissions. The Accessibility service is switched on only when you start a session. A visible banner shows while the screen is shared.
